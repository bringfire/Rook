# Three.js Rhino Stress Harness Design

Date: 2026-07-09
Status: ready for user review

## Purpose

Rook needs evidence about whether Three.js is a practical deterministic render
surface for distinct, animatable Rhino-derived objects before Rook adopts a new
scene-export contract or adds Three.js to any production runtime.

The first slice is an isolated experiment. It does not connect to live Rhino,
change Rook's production code, or define the final Rhino-to-Three.js exporter.
It measures browser behavior with reproducible synthetic scenes and local GLB
assets, including GLBs already generated by Rook.

## Decision

Create a self-contained browser experiment at:

```text
experiments/threejs-rhino-stress/
```

The experiment uses a locally pinned Three.js dependency and Vite. It is owned
by the Rook repository but isolated from RookNative, the managed companion, the
Python MCP server, installer, and release packaging. `node_modules`, generated
reports, and temporary assets are not committed.

Three.js source is not cloned. The experiment consumes the published package.
The initial Three.js version is `0.181.2`, matching the installed HyperFrames
Three.js adapter guidance at the time of design.

## Questions The Experiment Must Answer

1. How many distinct, independently addressable scene nodes can Three.js load,
   traverse, seek, and render comfortably on the local workstation?
2. At what geometry size, draw-call count, or material count does the browser
   become impractical for an animation workflow?
3. How much do shared meshes, parent grouping, coordinate rebasing, and static
   material merging improve load and render behavior?
4. Can absolute-time animation produce identical object transforms for the
   same requested time, independent of playback history?
5. Can stable actor metadata survive GLB import and support reliable lookup
   without depending on Three.js runtime UUIDs?

The experiment records observations. It does not establish universal hardware
budgets or production acceptance thresholds in the first slice.

## Scope

### In scope

- a local Vite browser application;
- pinned local Three.js imports with no CDN dependency;
- deterministic synthetic actor scenes at 100, 376, 1,000, and 10,000 nodes;
- configurable geometry density;
- shared-geometry and duplicated-geometry comparisons;
- individual-node and parent-group animation comparisons;
- near-origin and large-coordinate comparisons;
- stable actor identity stored as application metadata;
- local GLB file loading;
- an absolute-time scrubber and programmatic seek runner;
- performance and correctness reports displayed in the browser;
- focused automated tests for deterministic scene generation, actor lookup,
  transform evaluation, and report calculations.

### Out of scope

- live Rhino communication;
- changes to RookNative, Rook Companion, or MCP tool registration;
- a production Rhino scene-capture route;
- Brep, SubD, block, or render-mesh extraction from Rhino;
- automatic context-model generation;
- final glTF hierarchy, pivot, or material contracts;
- HyperFrames composition authoring or rendered video output;
- installer, deployment, publishing, or artifact-registry integration;
- remote assets, CDNs, analytics, telemetry, or network services;
- shipping Three.js as a Rook runtime dependency.

## Architecture

```text
Synthetic Scene Generator ----+
                               |
Local GLB File Loader ---------+--> Three.js Scene
                                      |
                                      +--> Actor Index
                                      +--> Absolute-Time Evaluator
                                      +--> WebGL Renderer
                                      +--> Metrics Collector
                                               |
                                               v
                                        Browser Report View
```

The experiment has five bounded units:

1. **Scene generator** creates deterministic synthetic actors from fixed input
   parameters and a fixed seed.
2. **GLB loader** accepts a user-selected local `.glb` file and returns the
   imported Three.js scene without uploading or copying the source elsewhere.
3. **Actor index** traverses a loaded scene and maps stable application actor
   IDs to `THREE.Object3D` instances.
4. **Absolute-time evaluator** computes transforms from requested time and
   immutable actor parameters. It does not use accumulated frame deltas.
5. **Metrics collector** samples structural counts, load timings, seek timings,
   and render timings, then presents a deterministic report payload.

These units communicate through plain data contracts so the experiment can be
discarded, retained, or promoted without coupling production Rook code to the
initial UI.

## Scene And Identity Model

Synthetic scenes use this hierarchy:

```text
Scene
  ActorSet
    ActorNode
      Mesh
```

Each actor node receives stable metadata:

```json
{
  "actorId": "synthetic_actor_000376",
  "actorSetId": "synthetic_set",
  "sourceKind": "synthetic"
}
```

Local GLB scenes are traversed for `userData.actorId`. Node names may be shown
for diagnosis but are not authoritative identifiers. Three.js-generated
`uuid` values are runtime details and are never used as durable actor IDs.

The actor index reports duplicate IDs, missing IDs, and malformed metadata.
Duplicate actor IDs fail the addressability check rather than silently choosing
one node.

## Geometry And Grouping Variants

Each synthetic run specifies:

- actor count;
- geometry density;
- geometry ownership: shared or duplicated;
- motion granularity: individual or parent group;
- coordinate mode: rebased or large-world-coordinate;
- material mode: shared or per-actor.

Shared geometry means distinct actor nodes reference the same immutable
`BufferGeometry` and compatible material. Each node retains an independent
transform and actor ID. Duplicated geometry allocates equivalent geometry per
actor to establish a deliberately expensive comparison.

Group animation changes a parent `THREE.Group` transform. Individual animation
changes each actor node's transform. Both modes preserve child addressability.

The large-coordinate variant offsets actors by a deterministic Rhino-like
world coordinate. The rebased variant subtracts a recorded scene origin before
rendering. The report records the origin and coordinate mode.

## Deterministic Time Contract

Render-critical animation is evaluated from an absolute time in seconds:

```text
state = evaluate(actorParameters, requestedTime)
```

The evaluator does not use `Date.now()`, `performance.now()`, Three.js `Clock`,
accumulated delta time, `requestAnimationFrame` history, or unseeded randomness
to determine scene state.

The browser may use `requestAnimationFrame` to schedule interactive display,
but every scheduled frame evaluates the scene from the current explicit time.
Programmatic tests can request any time in any order.

The deterministic-seek check evaluates selected times in forward, reverse, and
shuffled order. It hashes the resulting actor transform values after stable
numeric serialization and requires identical hashes for identical times within
the same test configuration.

This contract mirrors the behavior required for a later HyperFrames
`hf-seek` integration without adding HyperFrames to the first slice.

## Browser Interface

The interface remains functional rather than productized. It contains:

- a source selector for synthetic scene or local GLB;
- synthetic controls for actor count and comparison variants;
- build/load, run, stop, and reset controls;
- an absolute-time scrubber;
- a compact live status area;
- a structural and performance report table;
- an error panel that preserves the last failed configuration.

The default synthetic configuration uses 376 actors because it matches the
existing Pearson roof actor-set size observed during design exploration.

The harness does not automatically run the 10,000-node case on page load.
Expensive cases require an explicit user action.

## Metrics And Report Contract

Each completed run reports, when supported by the browser:

- Three.js revision;
- browser user agent and renderer identity;
- source kind and test configuration;
- load or construction duration;
- scene traversal duration;
- node, actor, mesh, material, triangle, and draw-call counts;
- actor IDs discovered, duplicate IDs, and missing-ID counts;
- seek sample count, average seek time, and worst seek time;
- render sample count, average render time, and worst render time;
- deterministic-seek pass or failure;
- independent-transform pass or failure;
- pivot sanity pass or failure;
- coordinate mode and recorded rebase origin;
- JavaScript heap observations only when the browser exposes them;
- warnings and failures.

Unsupported metrics are reported as unavailable. The harness does not replace
missing measurements with invented zero values.

The first slice displays the report in the browser and permits copying its JSON.
Automatic filesystem report persistence is deferred so the experiment does not
need a custom development server API.

## Correctness Checks

### Actor addressability

Every expected synthetic actor ID must resolve to exactly one object. Local GLB
files may lack actor metadata; this is reported as an addressability failure,
not a loader failure.

### Independent transforms

The harness transforms one sampled actor and verifies that unrelated actors do
not change. For shared geometry, it also verifies that geometry sharing remains
intact while transforms remain independent.

### Pivot sanity

Synthetic actors use a known local origin. A rotation check confirms the node
rotates around that origin without changing the expected pivot position.

This check diagnoses scene-graph behavior; it does not validate arbitrary Rhino
pivots in local GLBs because that requires the later Rook export contract.

### Deterministic seeking

Repeated evaluation of the same time must produce the same stable transform
hash regardless of evaluation order.

## Failure Handling

- WebGL initialization failure stops the run and reports the renderer error.
- GLB parse or load failure preserves the chosen filename and loader message.
- Duplicate actor IDs fail actor indexing.
- Missing actor metadata degrades local GLB addressability checks but does not
  prevent structural performance measurement.
- Non-finite transforms stop correctness evaluation and identify the actor and
  requested time.
- A stopped run cancels future samples and retains completed measurements.
- Browser memory-pressure termination cannot be caught reliably; the harness
  therefore requires explicit initiation of expensive test cases and displays
  the selected configuration before construction begins.
- Reset disposes geometries, materials, textures, and renderer-owned resources
  created by the previous run before building another scene.

## Testing

Focused automated tests cover:

- identical synthetic input produces identical actor parameters and IDs;
- requested actor counts produce the expected unique actor index;
- shared geometry preserves distinct actor transforms;
- duplicate IDs fail indexing;
- absolute-time evaluation is order-independent;
- large-coordinate and rebased configurations record the expected origin;
- report averages and worst-case calculations handle empty and populated
  samples without fabricating unavailable values;
- disposal visits generated resources without double-disposing shared assets.

Manual browser checks cover:

- all four actor-count presets;
- shared versus duplicated geometry;
- individual versus group animation;
- rebased versus large-coordinate scenes;
- local GLB loading;
- stopping and resetting an active run;
- WebGL console remaining free of unexpected errors.

## Repository And Dependency Policy

The experiment owns its `package.json` and lockfile. Production Rook projects do
not reference those dependencies. The experiment uses npm scripts for local
development, tests, and a production build check.

Generated directories and files are ignored locally, including:

- `node_modules/`;
- `dist/`;
- temporary GLBs copied solely for testing;
- generated report files if persistence is added later.

No Rook installer or deployment script discovers or packages this experiment.

## Acceptance Criteria

The first slice is complete when:

- the experiment installs independently from its directory;
- its automated tests pass;
- its production build succeeds;
- the browser harness runs synthetic scenes at 100, 376, 1,000, and 10,000
  actors only when requested;
- stable actor lookup and independent transforms are verified;
- shared and duplicated geometry variants are measurable;
- rebased and large-coordinate variants are measurable;
- absolute-time seek determinism is verified;
- a local GLB can be loaded without a network request;
- structural and timing results are visible and copyable as JSON;
- no production Rook project, runtime, installer, or deploy artifact depends on
  Three.js or Vite.

## Follow-On Decision

After the measurements are reviewed, Rook may design a separate production
scene-package contract. That later design can reuse the existing bounded native
capture patterns, GLB writer and validator, Director actor metadata, and
artifact-safety policies. It must separately define Rhino render-mesh capture,
block expansion, local pivots, hierarchy, context simplification, material
policy, coordinate conversion, and HyperFrames integration.

No production exporter work is implied by completion of this experiment.
