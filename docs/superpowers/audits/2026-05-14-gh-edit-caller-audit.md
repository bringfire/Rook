# GH Edit Caller Audit

Date: 2026-05-14

Spec: `docs/superpowers/specs/2026-05-14-gh-edit-partial-failure-contract-design.md`

## Contract States

| State | Semantics |
| --- | --- |
| Full success | success true, no partial_success, no top-level errors; safe to build on. |
| No-mutation failure | success false, verified false, top-level errors, no partial_success; safe to retry only after fixing input. |
| Partial mutation failure | Phase 1 success true + partial_success true + verified false + top-level errors; Phase 3 success false with same partial metadata; not automatically retryable. Inspect snapshot/edit summary, then remediate, undo, clean up, or deliberately retry with duplicate prevention. |

## Phase 3 Completion Notes

- Helper default and production caller flags now make mutation-backed `gh_edit` errors strict failures.
- `_record_gh_to_session` records `success: false` plus `partial_success: true`, and session serialization persists partial metadata.
- Batched GH intent fallback treats `partial_success` as non-retryable without inspection.
- `gh_replay_recipe` applies the same contract and records strict partial outcomes.
- Tests that asserted success for partial edit errors now expect strict failure, except for the single explicit helper compatibility test.
