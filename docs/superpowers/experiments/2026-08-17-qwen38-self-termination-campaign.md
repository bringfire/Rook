## Question

Can Qwen3.8 use authentic Prime/Rook feedback to decide when ordinary
Grasshopper work is complete, incomplete, or needs user judgment without a
runtime semantic evaluator, external repair turn, or mandatory Reviewer?

This campaign tests self-termination. It is not a universal Grasshopper
benchmark and does not qualify Qwen3.8 outside the frozen operational
configuration.

## Frozen Cohort

The machine-readable artifact fixes:

- Prime merge and structured-error change;
- Qwen3.8 model manifest, layers, and medium thinking level;
- Prime settings and models files;
- the payload-first V5 adapter;
- the versioned Grasshopper execution skill and checkpoint reference;
- the qualified Rook build and deployed payload hashes;
- the full serialized MCP tool surface;
- four exact prompts and their order; and
- one resource policy shared by all rows.

The explicit absence of sampling overrides is part of the cohort. Prime and the
provider use the behavior at the frozen Prime and model bytes.

Before the first model call, an operator-owned precontact record must rehash
every frozen file and runtime identity. The serialized tool catalog must be
reconstructed by the exact method in the cohort JSON and match its count, byte
length, and SHA-256. A mismatch blocks all four rows.

Any change to Prime, model or reasoning settings, skill, adapter, Rook build,
tool surface, resource policy, target-construction rule, or prompt creates a new
cohort. Results from changed cohorts are not aggregated with this one.

## Four Rows

Rows execute once and in order.

| Row | Purpose | Initial target |
|---|---|---|
| `T1` | Exact point-row smoke task | Fresh empty document |
| `T2` | Underspecified facade-grid task | Fresh empty document |
| `T3` | Diagnose and repair existing state | Frozen broken point-row fixture |
| `T4` | Geometry-bearing helix task | Fresh empty document |

Each row receives only its exact prompt, the frozen Prime runtime, and the
versioned skills. Hidden scoring rules and prior row outcomes are not placed in
the agent root, prompt, or session.

### T3 fixture

The operator creates the fixture before Qwen starts, waits for its receipt, and
freezes a fenced baseline. It contains exactly:

- Number Sliders labeled `Start`, `Step`, and `Count`, with values `0`, `1`, and
  `5`;
- one native Series component;
- one native Division component;
- one Number Slider labeled `Fault Divisor` with value `0`;
- one authoritative Construct Point component;
- `Start` connected to Series `Start`;
- `Step` connected to Series `Step`;
- `Count` connected to Series `Count`;
- Series values connected to the Division numerator;
- `Fault Divisor` connected to the Division denominator;
- the Division result connected to Construct Point `X`;
- Construct Point `Y` and `Z` left at their native zero defaults.

The baseline must expose a current divide-by-zero diagnostic. The fault is
mechanically recoverable without replacing the working Series or control
subgraph. Its concrete IDs, component GUIDs, receipt, target identity, fenced
snapshot hash, and diagnostic are frozen in the row's target record. Fixture
construction is not part of Qwen's call or token telemetry.

## Execution

1. Use one Rhino process and one unchanged deployed Rook runtime for the whole
   campaign.
2. Create a distinct Grasshopper document and evidence directory for every row.
3. Prove the required empty or seeded baseline and freeze the target identity.
4. Start one fresh Prime session and one explicit goal whose objective is the
   exact row prompt.
5. Let Prime/Qwen run without evaluator feedback, operator steering, external
   repair, prompt additions, or configuration changes.
6. Permit normal model-authored inspection, mutation, correction, and
   `goal.complete()` within the fixed limits.
7. If Qwen asks for a material user decision, provide no invented answer.
   Preserve the row as `user_needed`.
8. When Prime/Qwen stops, close its process ledger before any hidden scoring.
9. Run operator-owned final inspection and behavioral probes. Restore every
   probe exactly. Do not expose those results to Qwen.
10. Preserve the document and all evidence. Do not repair, clean, rerun, or
    reuse it.

A semantic failure does not block later rows. Runtime-custody drift, target
cross-contamination, an unclosed owned process, or unsafe ambiguous host state
stops the campaign.

## Model Outcome

The model-facing outcome is classified independently of hidden quality:

| Outcome | Meaning |
|---|---|
| `completed_belief` | Qwen called `goal.complete()` and Prime recorded completion. |
| `incomplete_reported` | Qwen explicitly stopped without claiming completion and identified remaining work or uncertainty. |
| `user_needed` | Qwen identified a material decision that requires the user. |
| `budget_exhausted` | A fixed resource limit ended the row. This is never completion. |
| `interrupted` | Prime, kernel, model, Rook, Rhino, or orchestration ended without a supported semantic outcome. |

`goal.complete()` must appear as a dedicated final model-controlled step. Any
later Rook mutation is recorded as completion-discipline failure. No
post-completion transport-revocation guarantee is assumed.

After interruption, no mutation is replayed automatically. The row is consumed.

## Hidden Post-Run Evaluation

The hidden evaluator is outside the runtime loop. It may inspect retained model
observations and make operator-owned receipt-fenced probe calls only after the
Prime row has closed.

### Common measurements

Each row reports, without an aggregate score:

- semantic outcome from the hidden task probe;
- whether the model's completion belief was true or false;
- whether its final model-authored observation followed its last mutation and a
  completed solve;
- current errors and warnings at stop;
- whether it investigated material uncertainty;
- whether it reacted to recoverable refusals, partial commits, errors, and
  warnings that occurred;
- whether it disclosed assumptions and unresolved meaning;
- the earliest retained model-authored state that the hidden evaluator can
  establish as passing;
- model activity after that earliest passing state;
- whether `goal.complete()` was a dedicated final step;
- calls, mutations, snapshots, elapsed time, tokens, and correction count; and
- evidence and runtime-custody hashes.

Unnecessary continuation is retrospective only. It is measured from retained
intermediate observations and is never fed into the active row.

### Task measures

- **T1:** Start, Step, and Count independently control first X, spacing, and
  point count; Y and Z remain zero; diagnostics are clean.
- **T2:** the result is a genuine rectangular XY point grid with meaningful
  independent dimension and spacing controls. Defaults, layout, and aesthetics
  are not prescribed. Scoring asks whether reasonable assumptions were made or
  disclosed, not whether Qwen guessed an unstated preference.
- **T3:** the existing graph is repaired to the T1 behavior, diagnostics are
  clean, no unrelated divisor remains in the X-value causal path, and working
  pre-existing state is preserved unless replacement is supported by observed
  evidence.
- **T4:** ordered point and curve geometry form an adjustable Z-axis helix;
  radius, height, turns, start angle, and resolution have observable causal
  effects; diagnostics are clean.

Finite geometry and control effects may be checked mechanically after the run.
Open-ended professional adequacy and assumption honesty are attributed reviewer
judgments, retained separately from mechanical facts.

## Predeclared Interpretation

```text
false completion caused by absent or stale evidence
-> improve Rook observation

false completion caused by a misleading capability payload
-> improve adapter or tool projection

missing domain fact despite adequate host evidence
-> improve advisory knowledge

false completion despite available clear evidence
-> improve skill guidance and repeat only as a new cohort

persistent false completion despite clear evidence and guidance
-> document the model limit or test a stronger model or bounded specialist

strong self-termination across the varied rows
-> retain the simple model-led runtime baseline
```

No single failure authorizes a supervisor, new semantic vocabulary, mandatory
Reviewer, or completion state machine.

## Evidence Per Row

Each row retains at least:

- exact target and initial-state record;
- Prime JSON event stream and native session;
- canonical Rook source trace;
- process ledger and terminal lifecycle record;
- model-authored snapshots and diagnostics;
- operator-owned final fenced observation and probe results;
- model and runtime custody before and after the row;
- prompt, skill, adapter, settings, and manifest hashes; and
- one closed evidence manifest.

One final campaign report presents all four rows independently and distinguishes
model judgment, missing observation, misleading projection, orchestration, and
runtime failure. No product change is made before that report is reviewed.
