fal queue exposes a `cancel_url` in the submit envelope (e.g., `https://queue.fal.run/{model}/requests/{request_id}/cancel`). Live cancellation was not exercised against the running job. Cancellation remains an open follow-on (see spike doc Open Follow-Ons) and does NOT block the Phase 1 lifecycle binding for Decision 1 — the cancel URL's existence is sufficient evidence that fal queue supports cancellation; the operational semantics (billing, idempotency, in-flight behavior) can be characterized in Phase 1 implementation or a Phase 2 follow-up.
